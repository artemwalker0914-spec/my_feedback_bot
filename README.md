# Бот «ЮНИВЁРСУМ» — обновлённая версия

## Что изменилось

1. **Постоянное хранение (SQLite, файл `univ_bot.db`)** — вместо словарей в
   памяти. Комнаты, участники, роли и карта «кто автор какого сообщения»
   переживают перезапуск бота. Смотрите `storage.py`.
2. **Комнаты на несколько участников** — один `topic` (тема) в группе теперь
   привязан не к одному ученику, а к комнате (`rooms`), в которой может быть
   ученик + один или несколько родителей.
3. **Роли** (`student`, `parent`, `teacher`) хранятся в базе и подписываются
   в пересылаемых сообщениях («📩 Сообщение от Родителя: ...») — имя и ID
   отправителя по-прежнему не раскрываются.
4. **Точная маршрутизация ответов** — раньше ответ учителя в теме уходил
   «ученику этой темы» вообще без учёта того, кто именно написал исходное
   сообщение. Теперь бот запоминает автора **каждого** пересланного
   сообщения (`message_map`) и Reply уходит именно этому человеку — так что
   если в комнате два родителя и ученик, ответ на конкретный вопрос получит
   только его автор.

## Настройка перед запуском

Задайте переменные окружения (на Bothost — в настройках приложения, не в коде):

| Переменная      | Назначение                                              |
|-----------------|----------------------------------------------------------|
| `BOT_TOKEN`     | токен бота от @BotFather                                  |
| `GROUP_CHAT_ID` | ID супергруппы с форум-темами (отрицательное число)        |
| `ADMIN_IDS`     | Telegram ID администраторов через запятую, напр. `111,222` |
| `DB_PATH`       | (необязательно) путь к файлу базы, по умолчанию `univ_bot.db` |

⚠️ **Токен в исходном файле был "зашит" в код и уже засветился — его нужно
отозвать/перевыпустить через @BotFather** (`/revoke`), а новый указывать
только через переменную окружения.

⚠️ **Важно для Bothost**: если хостинг пересоздаёт файловую систему
контейнера при каждом деплое/рестарте, файл `univ_bot.db` будет стираться
вместе с ней — и проблема «бот всё забывает» вернётся, только уже на уровне
SQLite. Убедитесь, что `DB_PATH` указывает на постоянный (persistent) том,
который Bothost не пересоздаёт. Если такого тома нет — на первое время
можно синхронизировать `univ_bot.db` во внешнее хранилище (например,
заливать на S3-совместимое хранилище при старте/остановке), либо перейти на
внешнюю БД (PostgreSQL) — сама структура `storage.py` рассчитана на замену
SQLite на другую БД без переделки остального бота.

## Права бота в группе

Бот должен быть администратором супергруппы с правами:
- «Управление темами» (создание/переименование топиков);
- «Отправка сообщений».

## Как это работает по шагам

1. `/start` от ученика или родителя → если для него нет отложенного
   приглашения, создаётся новая комната и тема в группе.
2. `/add_parent @username` или `/add_parent 123456789` — ученик или уже
   добавленный родитель приглашает второго родителя. Если тот уже писал
   боту раньше — добавляется сразу. Если нет — приглашение сохраняется и
   срабатывает автоматически, как только человек напишет `/start`.
3. `/add_teacher <user_id>` — только для ID из `ADMIN_IDS`.
4. `/setrole <user_id> <student|parent|teacher>` — только для администратора.
5. `/myrole` — пользователь узнаёт свою роль.
6. Личное сообщение любого участника комнаты → в тему уходит служебная
   пометка с ролью, затем копия сообщения (без "Forwarded from").
7. Ответ (Reply) на это сообщение в теме → уходит **только** автору
   исходного сообщения, а не всем участникам комнаты.

## Ограничения, о которых стоит знать

- Приглашение по номеру телефона (`/add_parent +7...`) не реализовано —
  Telegram Bot API не позволяет находить пользователей по телефону без
  того, чтобы они сами не поделились контактом с ботом. Сейчас поддержаны
  `@username` и Telegram ID; при желании можно добавить шаг с кнопкой
  «Поделиться контактом» для номера.
- Учитель добавляется командой `/add_teacher` глобально (ему присваивается
  роль), а не «в конкретную комнату» — потому что учитель и так видит все
  темы группы, будучи её участником; специально ограничивать его одной
  комнатой не требовалось по ТЗ.
